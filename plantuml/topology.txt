title BFT-SDN: Topology Update (Link Event) & UI Visualization

actor Switch as SW
participant "POX Primary\n(openflow.discovery)" as POX_P
participant "PBFT Dealer" as DEALER
collections "PBFT Nodes (N)" as PBFT_NODES
participant "POX Replica X" as POX_R_X
actor "Admin/User" as USER
participant "Streamlit UI\n(Blockchain Viewer)" as UI

group Link Discovery and Initial Report by Primary
    SW -> POX_P: LLDP Packet / Link State Change
    POX_P -> POX_P: Handles LinkEvent (e.g., link UP/DOWN)
    POX_P -> DEALER: gRPC: ReportLinkEvent(LinkEventInfo with Timestamp)
    DEALER -> DEALER: Creates LinkEventInput PBFT Tx
end

group PBFT Consensus on Link Event
    DEALER -> PBFT_NODES: Broadcasts LinkEventInput Transaction (via sender)
    loop for each PBFT Node
        PBFT_NODES -> PBFT_NODES: Receives Tx, adds to Pool
    end
    PBFT_NODES -> PBFT_NODES: Proposer includes Tx in Block
    PBFT_NODES <-> PBFT_NODES: PBFT Consensus (Pre-Prepare,\nPrepare, Commit)
end

group Block Commit and Replica Notification
    loop for each PBFT Node (e.g., Node X) that commits the block
        PBFT_NODES -> PBFT_NODES: Extracts LinkEventInput from committed block
        PBFT_NODES -> POX_R_X: gRPC: NotifyLinkEvent(LinkEventInfo)
        note right of PBFT_NODES : Node X notifies its assigned Replica X
        POX_R_X -> POX_R_X: Updates internal topology_active_links
        POX_R_X --> PBFT_NODES: gRPC: Empty (Ack)
    end
    note over PBFT_NODES,POX_R_X: This ensures all POX Replicas\nbuild a consistent topology view
end

group UI Fetches and Displays Topology
    USER -> UI: Opens/Refreshes Topology Viewer
    UI -> PBFT_NODES: HTTP GET /fetches entire blockchain JSON\n(from one PBFT Node's httpChain endpoint)
    PBFT_NODES --> UI: HTTP Response (JSON Array of Blocks)
    UI -> UI: Parses Blocks, extracts all LinkEventInput Txs
    UI -> UI: Reconstructs active_links_from_chain (topology)
    UI -> USER: Displays Network Graph & Switch Details
    note right of UI : Typically queries one designated node,\n but any node should have the committed chain
end
@enduml
